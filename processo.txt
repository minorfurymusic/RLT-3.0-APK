PARTE 1 — CÉREBRO (IA / "RLT ENGINE") — PRIORIDADE MÁXIMA
--------------------------------------------------------------------------------
Referência: src/lib/brainOrchestrator.ts (1254 linhas), brainOrchestratorTest.ts,
lib/i18n.ts, lib/imageCompressor.ts, lib/logger.ts, lib/version.ts,
components/AIAssistant.tsx (817 linhas) no repositório C-rebro.
Hoje nosso AIAssistant.tsx tem 173 linhas e é só um chat sem execução de
comandos — é o maior gargalo funcional do app inteiro.

1.1 Motor de comandos em linguagem natural (núcleo do Cérebro)
  [ ] Criar src/lib/brainOrchestrator.ts (ou equivalente nativo) capaz de:
  [ ]   Segmentar frases com múltiplas intenções numa mesma mensagem
        (ex.: "bebi 200ml de água e fiz supino com 40kg" = 2 ações)
  [ ]   Classificar cada segmento por domínio: ÁGUA / REFEIÇÕES / TREINO /
        EXAMES / AGENDA / MEDICAMENTOS / PERFIL / TEMA / CONSULTA (query)
  [ ]   Executar a ação real no HealthContext (CRUD) para cada domínio,
        não apenas responder em texto
  [ ]   Extrair e simplificar nomes automaticamente (ex.: frase longa sobre
        treino de peito → título "Supino Reto"; frase sobre exame →
        "Hemograma Completo")
  [ ]   Interpretar datas em linguagem natural corretamente ("dia 15 de
        julho", "12/08 às 15h30", "a partir de 15/07") e gravar na data
        certa, não sempre "hoje"
  [ ]   Medicamentos contínuos: registrar apenas a data de início e gerar
        os eventos futuros de dose automaticamente (não duplicar todo dia
        manualmente)
  [ ]   Alterar objetivo do perfil por comando de voz/texto (ex.: "meu
        objetivo agora é emagrecimento" → muda Weight Loss/Muscle
        Gain/Maintenance/Health)
  [ ]   Alternar tema claro/escuro por comando
  [ ]   Corrigir dados existentes por comando ("na verdade minha altura é
        180cm, corrige")
  [ ]   Manter um log de auditoria/transação (transactionLog) de tudo que
        o Cérebro executou, para poder depurar o que ele fez
  [ ] Criar um harness de teste (equivalente a brainOrchestratorTest.ts)
      que roda uma bateria de frases de teste e confere se cada domínio
      foi corretamente identificado/executado

1.2 Reconstrução do AIAssistant.tsx
  [ ] Roteamento local primeiro (usa o orchestrator acima) e só cai na
      chamada de IA generativa quando não for um comando estruturado —
      evita gastar chamada de API para "bebi 200ml de água"
  [ ] Histórico de múltiplas sessões de conversa, persistido localmente
      (criar/apagar/fixar/renomear/buscar sessão)
  [ ] Limite de 15 mensagens visíveis com botão de expandir/ver histórico
      completo (evitar conversa crescendo infinitamente na tela)
  [ ] Scroll automático para novas mensagens
  [ ] Entrada por voz (gravação de áudio, tratamento de erro de permissão
      de microfone)
  [ ] Anexo de imagem/arquivo na conversa, com compressão antes de enviar
      (ver 1.3)
  [ ] Tratamento diferenciado de erro: distinguir "sem internet", "chave
      inválida", "limite de cota/rate limit (429/503)" e mostrar mensagem
      específica em vez do genérico "Ops, estou com dificuldades de
      conexão" — se possível, mostrar um resumo dos dados do dia como
      fallback quando a IA estiver indisponível
  [ ] Quando a chamada de IA falhar, o app não pode travar/branquear —
      cair graciosamente (depende também do ErrorBoundary da Parte 4)

1.3 Suporte / utilidades do Cérebro
  [ ] lib/imageCompressor.ts (ou equivalente nativo) — reduzir imagem
      antes de enviar para IA (evitar OOM/timeout em celular)
  [ ] Parsing robusto de JSON vindo da IA — hoje o app faz
      `JSON.parse(response.text)` direto e quebra com resposta malformada;
      implementar reparo/recuperação de JSON (ex.: extrair bloco entre
      chaves, remover cercas de markdown, biblioteca tipo `jsonrepair`)
      antes de tentar parsear
  [ ] lib/logger.ts — captura global de erros (window.onerror /
      unhandledrejection nativo/WebView), persistir últimos N erros,
      permitir exportar relatório de diagnóstico
  [ ] lib/version.ts — versão de build exposta no app, diagnóstico de
      consistência (últimos builds, se há cache desatualizado)
  [ ] Bem-estar mental (MentalWellBeing em Home.tsx): CONFIRMAR que
      generateQuestions já usa contexto real (metas, rotinas, histórico
      médico, último score) para gerar perguntas dinâmicas via IA — isso
      já existe hoje, não recriar do zero. Investigar apenas se existe
      algum fallback estático quando a chamada de IA falha e, se sim,
      deixar esse fallback claro/rotulado como fallback, não substituir a

PARTE 2 — HEALTH CONNECT (substituto oficial do Google Fit) — PRIORIDADE 2
--------------------------------------------------------------------------------
Decisão confirmada: usar Health Connect (androidx.health.connect), não a API
legada do Google Fit (em descontinuação pelo Google) nem só o acelerômetro
puro do Capacitor. Health Connect precisa: (a) o app Health Connect instalado
no aparelho (nativo a partir do Android 14, instalável em versões antes
disso), (b) declarar permissões de leitura/escrita por tipo de dado, (c) o
usuário conceder essas permissões pela UI do próprio Health Connect.

2.1 Infraestrutura nativa
  [ ] Adicionar dependência do Health Connect Client
      (androidx.health.connect:connect-client) no build.gradle nativo
      Android
  [ ] Avaliar/instalar um plugin Capacitor de Health Connect existente ou
      escrever uma ponte nativa própria (plugin Capacitor customizado em
      Kotlin) se não houver plugin maduro o suficiente
  [ ] Declarar no AndroidManifest.xml as permissões novas necessárias:
      android.permission.health.READ_STEPS,
      android.permission.health.WRITE_STEPS (e demais tipos usados —
      distância, calorias ativas, frequência cardíaca, sono, peso —
      conforme o que for implementado abaixo)
  [ ] Também adicionar as permissões nativas de sensor que faltam hoje
      (confirmadas ausentes no diagnostico.txt): ACTIVITY_RECOGNITION,
      BODY_SENSORS, HIGH_SAMPLING_RATE_SENSORS, POST_NOTIFICATIONS,
      ACCESS_FINE_LOCATION, ACCESS_COARSE_LOCATION, FOREGROUND_SERVICE,
      FOREGROUND_SERVICE_HEALTH, FOREGROUND_SERVICE_LOCATION, WAKE_LOCK,
      RECEIVE_BOOT_COMPLETED
  [ ] Tela/fluxo de solicitação de permissões explicando ao usuário por
      que cada permissão é necessária (equivalente ao
      SystemPermissionsModal.tsx do C-rebro), com estado
      concedido/negado por permissão

2.2 Dados a sincronizar com Health Connect (substituindo os mocks atuais)
  [ ] Passos — LER de Health Connect. Isso corrige o bug crítico confirmado
      em HealthContext.tsx (getTodayValue hardcoded retornando 7240
      sempre) e os outros dois pontos que usam o mesmo fallback fixo
      (cálculo de calorias por passos)
  [ ] Distância percorrida (caminhada/corrida/ciclismo) — LER/GRAVAR
  [ ] Calorias ativas gastas — LER, usar no lugar do cálculo manual atual
      de "stepsBurned" em getDailyCalorieTarget
  [ ] Sessões de exercício/treino — GRAVAR no Health Connect quando o
      usuário registrar um treino no app (para aparecer também no
      Google Fit/outros apps de saúde do aparelho)
  [ ] Frequência cardíaca (se disponível no aparelho/wearable pareado) —
      LER, se fizer sentido no fluxo de treino
  [ ] Sono — avaliar LER se o app tiver alguma tela de sono (checar se
      HealthContext já modela isso; se não, não inventar tela nova só por
      causa do Health Connect, só documentar como pendência)
  [ ] Peso — sincronizar peso do perfil com Health Connect (leitura e
      escrita bidirecional, com o usuário podendo escolher a fonte de
      verdade)
  [ ] Sincronização em segundo plano: ler dados novos do Health Connect
      periodicamente mesmo com o app fechado (worker/serviço em segundo
      plano nativo — não existe hoje nenhum mecanismo de background sync
      no app)

2.3 Localização/GPS (complementar ao Health Connect, para trajetos)
  [ ] Rastreamento de distância via GPS para atividades ao vivo
      (caminhada/corrida/ciclismo), usando localização nativa com cálculo
      de distância — equivalente ao services/locationService.ts do
      C-rebro, adaptado para Health Connect quando aplicável
  [ ] Persistir atividade em andamento no estado global (HealthContext),
      não em estado local do componente — hoje uma atividade em progresso
      se perde se o usuário sair da tela de Exercícios
