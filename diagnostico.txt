3. BUGS CRÍTICOS E CONCRETOS (por severidade)
--------------------------------------------------------------------------------

[CRÍTICO] Login falso / sem autenticação real
  Arquivo: src/components/Login.tsx
  - Login é um stub local: usuário/senha fixos no código (`admin` / `123456`),
    sem backend, sem OAuth. Ao "logar", só grava `health_login=true` no
    localStorage. Qualquer pessoa pode ler o código-fonte do APK e descobrir
    a senha, ou simplesmente escrever a chave manualmente no localStorage via
    devtools para entrar sem senha nenhuma.
  - Na versão web, o login usa Google OAuth real (Firebase Auth) via
    `connectGoogleCalendar()`.

[CRÍTICO] Contagem de passos permanentemente falsa (mockada)
  Arquivo: src/context/HealthContext.tsx, linha ~607
  - `getTodayValue('steps')` retorna o valor fixo `7240` incondicionalmente,
    comentado no código como "Mocked synced steps". O mesmo número falso
    (7240) também é usado como fallback nos cálculos de calorias/passos em
    outros pontos do mesmo arquivo (linhas ~338 e ~439).
  - Resultado prático: o anel de passos na Home, o card de Score de Saúde e
    qualquer cálculo de calorias gastas por atividade estão sempre exibindo
    (ou influenciados por) um número inventado, nunca o valor real do usuário.
  - Causa raiz: não existe nenhum serviço de sensor (equivalente a
    src/services/sensorService.ts da versão web) nem o plugin
    @capacitor/motion instalado. O AndroidManifest.xml do app atual também
    NÃO possui as permissões ACTIVITY_RECOGNITION / BODY_SENSORS necessárias
    (ver seção 7).

[CRÍTICO] Chave de API do Gemini exposta no bundle do cliente
  Arquivos: src/services/aiMedicalService.ts, src/components/Home.tsx,
  src/components/Exercises.tsx (2x), src/components/Nutrition.tsx,
  src/components/AIAssistant.tsx
  - Em 5 pontos diferentes do código, `new GoogleGenAI({apiKey:
    process.env.GEMINI_API_KEY})` é instanciado diretamente no cliente,
    com a chave injetada em tempo de build (vite.config.ts define
    `process.env.GEMINI_API_KEY` estaticamente). Isso significa que a chave
    da API fica embutida no bundle JavaScript final, visível a qualquer
    pessoa que inspecione o APK/arquivos estáticos.
  - A versão web resolve isso com um proxy de servidor (server.ts, endpoint
    `/api/gemini`) e permite ao usuário configurar sua própria chave via
    Perfil, sem nunca embutir uma chave fixa no bundle.

[CRÍTICO] Sem tratamento de erros / sem tela de recuperação (crash = tela branca)
  Arquivos: src/main.tsx (não tem ErrorBoundary nenhum)
  - Qualquer exceção não tratada — por exemplo, `JSON.parse(response.text)`
    direto na resposta da IA em vários pontos (sem `safeJsonParse`/reparo de
    JSON malformado) — derruba o app inteiro para uma tela branca, sem log,
    sem opção de recarregar, sem diagnóstico.
  - A versão web tem: ErrorBoundary global, logger de erros persistente
    (lib/logger.ts, últimos 200 erros com expurgo de 30 dias, exportação de
    relatório de diagnóstico), parsing de JSON resiliente com biblioteca
    `jsonrepair`, e um DiagnosticModal acessível pelo próprio app.

[CRÍTICO] Botões e navegação "mortos" (sem função) no Perfil
  Arquivo: src/components/Profile.tsx
  - "Privacidade & Segurança", "Idioma" e "Ajuda & Suporte" são botões sem
    `onClick` (linhas ~298-305) — literalmente não fazem nada ao serem
    tocados.
  - O botão "Sair/Log Out" (linhas ~161-163) também não tem `onClick`.
  - Mesmo que os `onClick` fossem adicionados, as rotas
    `/profile/privacy`, `/profile/language` e `/profile/help` NÃO EXISTEM em
    src/App.tsx — falta tanto o componente quanto a rota.
  - Não há alternância de tema escuro/claro, não há configuração de unidades
    (métrico/imperial), não há tela de permissões do sistema, e não há
    NENHUMA forma de o usuário configurar sua própria chave de API Gemini.

[ALTO] Calendário anuncia sincronização que não existe
  Arquivo: src/components/Calendar.tsx
  - O modal "Agendar Evento" exibe o texto "Este evento será sincronizado com
    seu Google e Apple Calendar" — mas não existe NENHUM código de
    sincronização com Google/Apple Calendar no app atual (o campo
    `synced?: boolean` em types.ts existe mas nunca é usado/setado). É uma
    promessa falsa na interface.
  - A versão web implementa sincronização real via
    src/services/googleCalendarService.ts (Firebase Auth + Google Calendar
    REST API).

[ALTO] Assistente de IA ("Cérebro") é um chat simples, sem execução de comandos
  Arquivo: src/components/AIAssistant.tsx (173 linhas vs. 817 na versão web)
  - Não existe nenhum motor de interpretação de linguagem natural
    (equivalente a src/lib/brainOrchestrator.ts, 1254 linhas na versão web)
    capaz de, por exemplo, entender "bebi 200ml de água" e realmente
    registrar isso no app. Toda mensagem vai direto para a API Gemini, sem
    roteamento local, sem fallback offline, sem histórico de sessões
    persistente, sem entrada por voz, sem anexar imagens.
  - Sem redação de dados sensíveis (LGPD) antes de enviar informações de
    perfil/saúde para a IA.

[MÉDIO] Dados de saúde/perfil enviados sem anonimização para a IA (lacuna de
privacidade/LGPD)
  Arquivos: src/components/Home.tsx, src/services/aiMedicalService.ts
  - A versão web possui uma camada inteira de conformidade com a LGPD
    (src/lib/lgpd.ts): anonimização de peso/idade/localização antes de
    chamadas de IA e redação de PII em imagens médicas (borrão automático +
    marca d'água "LGPD ANONYMIZED"). O app atual não tem nada disso — envia
    dados de perfil e imagens médicas em texto/imagem crus para a API.

[MÉDIO] Registro de água ignora a data selecionada
  Arquivo: src/components/WaterTracking.tsx, linha ~20
  - Sempre grava novos registros de água contra `new Date()` (hoje), mesmo
    que o usuário esteja navegando por uma data passada em outra tela — bug
    de integridade de dados quando comparado à versão web, que usa a data
    selecionada global do contexto.

[MÉDIO] Categorias médicas inteiras ausentes
  Arquivos: src/components/HistoryForm.tsx, src/components/Medical.tsx,
  src/types.ts
  - Faltam por completo as categorias "Medicação Contínua" (com agenda de
    horários de dose e lembretes) e "Sinais Vitais de Rotina" (pressão
    arterial, glicemia, outros). Os tipos `ContinuousMedicationRecord` e
    `RoutineVitalsRecord` nem existem em types.ts do app atual — não é só
    UI faltando, é o modelo de dados que não suporta esses registros.
  - Não há gráficos de tendência de sinais vitais (a versão web usa
    `recharts` para isso em Medical.tsx); o app atual não tem a biblioteca
    `recharts` instalada.

5. BIBLIOTECAS/SERVIÇOS DE INFRAESTRUTURA INTEIRAMENTE AUSENTES
--------------------------------------------------------------------------------
  - src/lib/brainOrchestrator.ts (1254 linhas) — motor de comandos em
    linguagem natural ("RLT ENGINE V3"): entende frases livres, separa
    múltiplas intenções numa mesma frase, classifica por domínio (água,
    refeições, treino, exames, agenda, remédios, perfil, tema) e executa
    ações reais no app, com log de auditoria.
  - src/lib/i18n.ts (2136 linhas) — sistema completo de tradução/localização
    para 12 idiomas. O app atual não tem NENHUM sistema de tradução; todo
    texto está fixo (a maioria em inglês, misturado com português em
    alguns pontos).
  - src/lib/lgpd.ts — anonimização de dados sensíveis e redação de imagens
    antes de enviar à IA (conformidade com a Lei Geral de Proteção de Dados).
  - src/lib/logger.ts — captura global de erros, exportação de relatório de
    diagnóstico.
  - src/lib/version.ts — versionamento de build, diagnóstico de
    consistência de cache/service worker, "force purge & reload".
  - src/lib/imageCompressor.ts — compressão de imagens no cliente antes do
    upload (evita OOM/timeout em dispositivos móveis ao enviar fotos para a
    IA).
  - src/services/sensorService.ts — contador de passos real via acelerômetro
    nativo (@capacitor/motion), com detecção de picos, keep-alive em
    segundo plano e broadcast via service worker.
  - src/services/locationService.ts — rastreamento de distância via GPS
    (geolocation + fórmula de Haversine) para corrida/caminhada/ciclismo.
  - src/services/googleCalendarService.ts — login Google real (Firebase
    Auth) e sincronização bidirecional com Google Calendar.
  - server.ts — servidor Express próprio com proxy seguro para a API Gemini
    (evita expor a chave no cliente) e endpoint de health-check.
  - public/manifest.json, public/sw.js, ícones — o app atual não é
    instalável como PWA e não tem nenhuma capacidade offline/sincronização
    em segundo plano (Periodic Background Sync).
  - Integração Firebase — ausente por completo (nem no package.json nem no
    código); usada na versão web apenas para autenticação Google.

6. CONFIGURAÇÃO ANDROID NATIVA (APK) — PERMISSÕES AUSENTES
--------------------------------------------------------------------------------
Arquivo: android/app/src/main/AndroidManifest.xml

O app atual só declara `android.permission.INTERNET`. A versão de referência
declara adicionalmente (todas ausentes no app atual):
  - ACTIVITY_RECOGNITION, BODY_SENSORS, HIGH_SAMPLING_RATE_SENSORS
    → necessárias para contagem real de passos (explica o bug do "7240 fixo")
  - ACCESS_NETWORK_STATE
  - POST_NOTIFICATIONS
    → sem isso, notificações locais (lembretes de medicação, etc.) não
      funcionam no Android 13+
  - VIBRATE, WAKE_LOCK
  - FOREGROUND_SERVICE, FOREGROUND_SERVICE_HEALTH, FOREGROUND_SERVICE_LOCATION
    → necessárias para rastreamento em segundo plano (passos/localização)
  - ACCESS_FINE_LOCATION, ACCESS_COARSE_LOCATION
    → necessárias para rastreamento de distância via GPS
  - RECEIVE_BOOT_COMPLETED
    → necessária para retomar serviços após reiniciar o aparelho

Além disso, o app atual não tem os plugins nativos correspondentes instalados
(@capacitor/haptics, @capacitor/local-notifications, @capacitor/motion,
@capacitor/app), então mesmo adicionando as permissões no manifest, o código
JS ainda não teria como usá-las sem também adicionar essas dependências.

Outras diferenças de configuração nativa (build.gradle/styles.xml): a versão
de referência usa compileSdk/targetSdk 34 fixos (o app atual usa variáveis de
rootProject), tema com splash screen simplificado e cores da marca
(#4F46E5/#0F172A) aplicadas nativamente — diferenças cosméticas/de manutenção,
não bugs funcionais.
